# Assumptions and design decisions

The following choices document implementation assumptions and design decisions for the selected ColorKast scope. “Supported by SRS” means the behavior is directly supported by the supplied ABC Paint / ColorKast SRS v1.0. “Explicit design decision” means the SRS does not fully specify the implementation detail and a reasonable choice was made and documented.

| Choice | Basis | Implemented behavior / rationale |
|---|---|---|
| SQLite / server-rendered Flask | **Explicit design decision** | A single local relational database and small Python stack; no external runtime services. |
| Common color formats | **Explicit design decision** | RGB comma-separated triplets and 6-digit HEX, optional `#`, case-insensitive HEX. Whitespace around components/values is accepted. |
| Name search | **Explicit design decision** | Literal case-insensitive partial matching; SQL wildcard characters `%` / `_` are escaped. SQLite case folding is sufficient for the fictional English dataset; full Unicode case folding is not promised. |
| Number and color search | **Explicit design decision** | Exact number matching, case-sensitive; exact RGB equality. Duplicate numbers across collections/schemes return every match unless filtered. |
| Paint uniqueness | **Explicit design decision** | Unique `(paint_number, collection_id, scheme)`. Scheme selection in closest-color input disambiguates numbers shared by old/new schemes. |
| RGB validity | **Explicit design decision** | RGB is represented using standard 8-bit components, so each component is validated from 0 through 255 inclusive. |
| Distance formula | **Explicit design decision** | The SRS requires nearest-color matching in RGB color space. Euclidean RGB distance is used as the concrete distance metric; results are sorted using full precision and displayed rounded to three decimals. |
| Closest candidate policy | **Explicit design decision** | Includes both schemes in the target collection, including the source itself if in that collection (distance 0). Ties break by database ID. Any positive integer N is accepted; a larger N returns all candidates. |
| Translation collection isolation | **Supported by SRS** | Only old-scheme source and new-scheme mappings in the requested target collection; never substitutes another collection. |
| Multiple mappings | **Explicit design decision** | Duplicate identical pairs prohibited. If several mappings to a requested collection exist, show all; seeded data has at most one per source/target collection. |
| Company representation | **Explicit design decision** | Company is normalized on Collection and shown for every paint through that relation. The paint form requires company selection and rejects a mismatch with its collection. |
| Collection / mapping management | **Explicit design decision** | Four collections and translations supplied by seed; no optional CRUD screens for them. Existing names/RGB values of mapped paints can change; their scheme and collection cannot change through paint administration. |
| Referenced paint deletion | **Explicit design decision** | Reject when any translation references either side; enforced by route policy plus SQLite restrictive foreign keys. Unreferenced deletion preserves palette snapshots and sets their paint FK to NULL. |
| Browser palette identifier | **Explicit design decision** | A random UUID in Flask's signed `HttpOnly` session cookie; stored in SQLite with each palette item. Every display/delete/clear filters by the current UUID. No IDs are accepted from a form to choose another session. |
| Persistent session | **Explicit design decision** | Permanent cookie with a rolling 30-day lifetime. A stable environment secret allows restart persistence. Removing cookies or changing the secret loses palette access. This is browser/session privacy, not a secure customer account. |
| Admin session lifetime | **Explicit design decision** | Uses the same 30-day permanent session cookie; explicit logout removes admin authentication and keeps the browser palette. Login preserves palette UUID. Separate admin timeout / password-reset flows are outside scope. |
| Palette duplicates | **Explicit design decision** | Every addition creates a new timestamped entry, even when paint/RGB is repeated. Display newest timestamp then ID first. |
| Palette snapshots | **Explicit design decision** | Store name/number/collection text and RGB at save time. Later paint edits or deletion do not rewrite saved items. Chooser additions are always labeled Custom Color, even if an RGB match exists. |
| Palette expiry | **Supported by SRS** | 30 days per saved item. Before palette access/add/remove/clear, globally delete items with `added_at <= now - 30 days`. No scheduler: unaccessed stale rows are removed on the next relevant request and cannot be displayed. |
| Timestamps | **Explicit design decision** | UTC stored as naive SQLite datetimes; UI explicitly labels UTC. |
| Processing timing | **Supported by SRS** | `perf_counter` directly surrounds source lookup / DB query / materialization and closest distance calculation/sorting. No network time. |
| Timing boundaries | **Explicit design decision** | Exclude form validation, collection dropdown lookup, template rendering, and HTTP request setup. Return real UI and header timing for executed operations, including unsuccessful lookups; invalid forms have no timing. Four decimal milliseconds (scientific notation if exceptionally small). |
| Permissions | **Supported by SRS** | Explicit capability sets: add at 1–3, update at 2–3, delete at 3, create admins no higher than self. All admin pages are protected, including direct GET and crafted POST requests. |
| Login credentials | **Explicit design decision** | Usernames case-sensitive, new usernames 3–60 characters using ASCII letters/digits/underscore/dot/hyphen. Passwords 12–128 characters, Werkzeug scrypt hashes. Duplicate usernames rejected. Login accepts legacy seeded names; generic incorrect-credentials feedback. |
| Form limits | **Explicit design decision** | Paint/collection/company text up to 100 characters in the modeled data; paint number 40; search value 100; request body maximum 64 KiB. UI errors preserve useful submitted values; password values are never echoed. |
| Cookie Secure flag | **Explicit design decision** | Disabled for localhost HTTP; environment option enables it with HTTPS. Secret key required, minimum 32 characters; `.env` loads automatically and is ignored. |
| Modern browser / keyboard UI | **Explicit design decision** | Modern Chrome/Edge/Firefox/Safari with native color input; numeric RGB preview/save functions without JavaScript. Access-key modifiers depend on browser/OS. Delete/clear confirmation dialogs are a JavaScript usability aid; authorized no-JS POST still works. |
| Fictional seed | **Explicit design decision** | 40 invented paints across four collections, 20 mappings; no proprietary database copied. Seed is additive/idempotent on pristine data, preserves existing rows/passwords, and requires all three password variables each run. It is not a reset or password rotation command. |
| Small local scale | **Explicit design decision** | No pagination or migrations; full result lists and in-memory RGB ranking suit the assignment dataset. Indexes on paint name, number, collection, palette session and date; SQLite foreign keys enabled. |
| Color Sample Matcher | **Supported by SRS** | Low-priority optional image module excluded by the selected scope. No upload/image storage. |
| Palette selection behavior | **Explicit design decision** | The SRS describes storing recent color searches but does not specify whether every search result is stored automatically. The implementation saves a color when the user explicitly chooses “Add to palette” from search, translation, closest-color results, or the chooser; results are not automatically added. |

These decisions do not establish that performance, security, or usability NFRs passed their separate assignment evaluation.
